## 8. 実装後の裁定一覧（PR #87）

### 8.1 spec の誤記・書き漏れ

1. §4.6: `.text-highlight-text` の本体は `color:var(--highlight-text)`。`@theme inline` が値を展開するため、spec の `var(--color-highlight-text)` は誤り。実効値は §4.7 の computed color で突合する。
2. §4.7: `/components/` の Sidebar は document 全体では 2 件になる。2 件目は `[data-component-index-item="sidebar"]` 配下の inert な部品プレビューで、サイトのシェルとは無関係。`closest("[data-component-index-item]")` で除いた数（トップ 0 / 一覧 1 / 個別 1）をサイトの合格条件にし、両方の数値を記録する。
3. §2 / §3 は `scripts/*` を禁止範囲にしていたが、`scripts/catalog-build.test.mjs` の 2 件がトップの docs shell とサイドバー全件リンクを固定しており、1 カラム化と直接矛盾していた。同ファイルだけを許可範囲へ追加した。
4. §A.3: 現行の components 段落が「サイドバーの一覧または…」と書かれており、1 カラムのトップでは成立しない。文言を整え、`/components/` への導線を別途置いた。

### 8.2 運用

- commit の `Co-Authored-By` と PR 本文の `Generated with Claude Code` は、実装が Codex でも spec のまま付ける（司令塔の Claude Code が spec・裁定・完了ゲートを担った事実に基づく。過去 PR と一貫）。実体（実装 Codex、レビュー Sonnet、指揮と完了ゲートは司令塔）は PR 本文の「エージェント実装の来歴」節に書き分ける。
- 既存テストが新しい設計と矛盾する場合は、**削除・skip 化をせずに assert を新契約へ書き換える**。テスト件数を減らさず、守っていた性質（ここでは個別ページの網羅検査）は残し、検査が空走していないことを陽性対照で確かめる。
